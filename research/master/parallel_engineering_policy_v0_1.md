Date: 2026-10-15
Status: STABLE / MASTER-AUTHORIZED

## Purpose

This policy allows a strictly non-effect-bearing software-engineering/audit workstream to proceed in parallel with the currently authorized CORE scientific/pre-execution work, without weakening the project's anti-cherry-picking, freeze, seed, or application protections.

It supplements `PROJECT_GOVERNANCE.md` and `research/master/command_protocol_v0_2.md`.

## Parallel-lane rule

The default project rule remains one controlled scientific next action at a time.

MASTER may additionally authorize one isolated **engineering lane** in parallel when all of the following hold:

1. its outputs are DEVELOPMENT EVIDENCE or software/audit artifacts only;
2. it does not generate or inspect protected confirmatory data;
3. it does not change any frozen scientific model, truth, target, threshold, success criterion, or result;
4. it does not execute application-level performance experiments;
5. it uses a separate Git development branch and explicit provenance;
6. any later scientific use requires a separately frozen pre-execution contract.
